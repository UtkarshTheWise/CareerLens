**Frontend and integration, what to rely on**
- **Auth.** Send `Authorization: Bearer <Supabase access token>` on every call except `GET /health`. Bad, missing or expired token: `401 unauthorized` (same generic message always). First sign-in: `GET /v1/me` is `404` until `POST /v1/profiles` (one profile per account, a second is `409`). Another user's profile, analysis, quiz or application is `404`. Local work: `DEV_AUTH=1` (any request is the demo student and counts as staff).
- **Cohort routes** (`listCohorts`, `getCohortInsights`, `listCohortStudents`, `exportCohort`) are **placement staff only**: `403 forbidden` for students. Staff = a token whose email or user id is in `PLACEMENT_STAFF`, or whose Supabase `app_metadata.role` is `placement` (set by an admin; `user_metadata` never counts). The placement screens must handle 403 (hide the nav item or show "staff only"). In production someone must set `PLACEMENT_STAFF` or no one will see cohort data.
- **Limits.** JSON bodies over 1 MB and uploads over 6 MB get `413 payload_too_large` (`details.max_bytes`) with CORS headers; the 5 MB file rule still applies inside the upload. Every response carries `X-Request-ID` (exposed to browsers; quote it when reporting a bug).
- **`/health`** needs no token. It returns `200 {status, version, llm_provider}` only if the database answers, else `503 db_unavailable`. `llm_provider` is the provider that last answered in this process (or the first configured one).
- **`tailorResume`** (`POST /v1/applications/{id}/tailored-resume`) is real. It needs a finished analysis (`409 no_analysis`) and an application `description` of 40+ characters (`422 no_description`); LLM trouble is `429 llm_unavailable`, never an unchanged resume presented as tailored. `bullets[].original` is always the student's stored text; a rewrite appears only when it adds no unverified skill and no new number (otherwise `rewritten` equals `original`); `numbers_without_evidence` lists numbers in the student's own bullets that no verified fact backs (kept, not removed); `skills_order` is the verified skills, the job's own first. The extension's "tailor" button can show `rewritten === original` bullets as "no safe change".
- **Production behaviour.** `ENVIRONMENT=production` refuses to start with `DEV_AUTH=1` or without `SUPABASE_JWT_SECRET`/`SUPABASE_URL`. Logs are JSON lines, one per request (route template, status, ms; never bodies, queries, headers or tokens).
